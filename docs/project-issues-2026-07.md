Findings from a whole-project review (main + the unmerged
`claude/blend-weighted-engine` branch). Every item was verified against the

## Engine / scoring

### E1 — False precision: two-decimal scores in the elite band — MEDIUM
- **Where:** `src/lib/taste-engine.ts` (elite-band remap, `matchScore > 88` →
  89.00–92.00 with 2 decimals), `formatScore()` in `src/lib/utils.ts`.
- **What:** 91.63 vs 91.57 implies a resolution the inputs cannot support —
  the difference is generated by hand-tuned integer bonuses (+5 archetype,
  +3 adjacency…), not by measurement. `docs/engine-philosophy.md` itself names
  "false precision" as the #1 honesty risk, yet the UI displays the decimals.
- **Fix:** keep decimals internally for ordering (that part is sound), display
  whole numbers (or "91+") in the UI. Pure display change; engine untouched.
- **Effort:** small.

### E2 — behavioralFamily bonus (max +12) dominates sensoryFamily (+5) — MEDIUM
- **Where:** `src/lib/behavioral-family.ts` (`familyBonus`),
  `taste-engine.ts` bonuses; already tracked as `deferred-improvements.md` #2.
- **What:** "right effect-family, wrong smell" candidates (GG4 fan → GMO
  Cookies) get lifted to the ceiling above genuinely same-smell strains.
- **Fix:** Option A from the backlog — cap behavioralFamily to +8 when the
  sensory families are unrelated. Verify with `scripts/score-distribution.ts`
  + stress snapshot diff before/after.
- **Effort:** medium (the fix is small; the recalibration check is the work).

### E3 — Potency channel barely discriminates — LOW
- **Where:** `src/lib/strain-data.ts` (`potency` values), `potencyContribution`
  in `taste-engine.ts`.
- **What:** 518/895 strains are `strong` and 211 `very-strong` (81% in the top
  two of four buckets; only 6 `mild`). A "mild" preference penalises almost the
  whole catalog uniformly; a "strong" preference rewards almost everything.
- **Fix:** re-curate potency toward a real distribution (or accept and
  document that the channel is a dislike-guard, not a ranker).
- **Effort:** medium (curation), or small (document the limitation).

### E4 — Keyword fallback for unknown strains produces confident-looking reads — LOW
- **Where:** `inferStrain` / `BUCKETS` in `taste-engine.ts`.
- **What:** any unknown name containing e.g. "sour" is read as citrus/sativa;
  no keyword hit → generic "earthy/sweet/relaxed hybrid". Confidence is capped
  at low/medium and the risk note says "inferred from the name" — good — but
  the numeric score still renders at full size next to curated ones.
- **Fix:** visually mute inferred-strain scores (e.g. "~62") or badge them
  more loudly than the current footnote.
- **Effort:** small.

### E5 — Prisma rows cast into engine input via `as unknown as TasteProfileInput` — LOW (tech debt)
- **Where:** `merge-worlds.ts:233,269,302`, `src/app/catalog/page.tsx:56`,
  and siblings.
- **What:** the Prisma `TasteProfile` model and the engine's input type are
  kept in sync by hand; NULL-vs-undefined bugs already bit once (see the
  defensive `?? []` seam in `taste-engine.ts` around texture/quality). Any new
  engine field silently defaults through the cast.
- **Fix:** one `toEngineInput(p: TasteProfile): TasteProfileInput` adapter that
  normalises every field; ban the raw cast.
- **Effort:** small.

### E6 — All calibration is intuition on single cases; zero user validation — STRUCTURAL
- **Where:** every weight/bonus constant in `taste-engine.ts`;
  `deferred-improvements.md` #4 admits "~0 real users".
- **What:** not a bug — a standing caveat. The feedback loop's math is bounded
  and sane but empirically unvalidated; the 89–92 band shape, W weights, and
  bonus magnitudes rest on a handful of expert-review cases.
- **Fix:** nothing to code now. When RunAudit + StrainFeedback accumulate,
  re-derive weights from real verdicts (the audit versioning v1→v9 already
  makes eras comparable). Keep this item open as the reminder.
- **Effort:** n/a (data-gated).

## Blend-target branch (`claude/blend-weighted-engine`, not wired in)

### B1 — Penalty constants are huge and calibrated on one case — HIGH (for that branch)
- **Where:** `src/lib/blend-target.ts` — `OVERSHOOT = 46`, `UNDERSHOOT = 42`,
  `ON_TARGET = 10`; the comment itself says "Calibrated on the gas+20%-sweet
  case; retune broadly against scripts/stress".
- **What:** one minor side can swing a strain by ~30+ points on a 0–100 scale;
  with 2 minor sides penalties can exceed the whole fit signal.
- **Fix:** sweep the constants against the full stress archetype set and a
  blend-specific report (extend `scripts/blend-report.ts`), not one recipe.
- **Effort:** medium.

### B2 — Equal shares pick an arbitrary dominant — HIGH (for that branch)
- **Where:** `blend-target.ts` `domIdx` reduce with strict `>`.
- **What:** at 50/50 the first member in array order becomes "dominant" and the
  other gets minor-side prominence penalties — a symmetric recipe behaves
  asymmetrically depending on profile order.
- **Fix:** treat near-equal shares (within ε) as co-dominant: either skip
  minor-side penalties for them or apply the closeness term symmetrically.
- **Effort:** small.

### B3 — Unknown strains always register as undershoot — MEDIUM
- **Where:** `blend-target.ts` `characterLevel` returns 0 when
  `findStrain(name)` misses (inferred/AI-resolved strains aren't in STRAINS).
- **What:** any off-catalog strain is charged UNDERSHOOT for "missing" a note
  it may well carry; blends systematically bury unknown menu items.
- **Fix:** resolve through the same `resolveStrain`/overrides path the engine
  uses, and/or scale the closeness term by data confidence.
- **Effort:** small-medium.

### B4 — weightedFit averages post-calibration matchScore — MEDIUM
- **Where:** `blend-target.ts` (`scoreStrain(...).matchScore`).
- **What:** matchScore has anchor floors (94–96) and the elite band remap baked
  in; averaging it re-imports those display artifacts into a new formula. A
  favourite-anchored strain in one profile drags the blend average up by fiat.
- **Fix:** compute fit from `unclampedScore` (already exposed for exactly this
  kind of use), calibrate the output scale once at the end.
- **Effort:** small.

### B5 — No tests, not wired in — MEDIUM
- **Where:** the branch adds `blend-target.ts` only; nothing imports it and no
  test covers `scoreBlendTarget`.
- **Fix:** before wiring: unit tests (dominant unaffected, overshoot sinks
  cloying, undershoot prefers light-note presence, 50/50 symmetry after B2,
  determinism), then an opt-in flag in the blender path.
- **Effort:** medium.

## App / security

### A1 — No CSRF protection on state-changing routes — MEDIUM
- **Where:** all `src/app/api/**` POST/DELETE handlers; session cookie is
  `sameSite: "lax"`.
- **What:** Lax blocks cross-site POST from forms/fetch in modern browsers, so
  practical exposure is limited — but there is no token as defence-in-depth,
  and any future GET-with-side-effects or older-browser traffic is exposed.
- **Fix:** double-submit token or origin-check middleware on mutating routes.
- **Effort:** small-medium.

### A2 — Rate limiting is per-instance, in-memory — MEDIUM
- **Where:** `src/lib/rate-limit.ts` (documented as a guardrail);
  `clientIp` trusts the first `x-forwarded-for` token.
- **What:** on serverless/multi-instance deploys the login/signup limits are
  per-cold-start and effectively decorative; XFF is spoofable when not behind
  a trusted proxy.
- **Fix:** shared store (Upstash/Redis) behind the same call sites (the file
  already anticipates this); read client IP from the platform's trusted header.
- **Effort:** small-medium.

### A3 — No session revocation — MEDIUM
- **Where:** `src/lib/session.ts` — stateless HMAC cookie, 30-day TTL.
- **What:** a leaked cookie stays valid for 30 days; the only kill-switch is
  rotating `AUTH_SECRET`, which logs out everyone. Password reset does not
  invalidate existing sessions.
- **Fix:** add a per-user `sessionEpoch` (int) checked in `getUserId`; bump it
  on password reset / "log out everywhere". One indexed column, no session
  table needed.
- **Effort:** medium.

### A4 — Password policy is length ≥ 8 only — LOW
- **Where:** `src/lib/password.ts:64`.
- **Fix:** raise to 10+, optionally add a top-10k-common-passwords denylist.
  Scrypt params are fine.
- **Effort:** small.

### A5 — Signup adopts the anonymous cookie's user row (fixation window) — LOW
- **Where:** `src/app/api/auth/signup/route.ts` (account written onto the
  visitor's existing anonymous row).
- **What:** deliberate and useful (profile carries over), but if an attacker
  can plant their own valid anonymous cookie in a victim's browser (XSS or
  subdomain cookie injection), the victim's later signup lands on an
  attacker-known userId. Low practical likelihood; worth a mitigation.
- **Fix:** rotate to a fresh userId at signup when the anonymous row has no
  profile data worth migrating; or re-issue the cookie (new signature) on
  signup so a planted token can't be replayed.
- **Effort:** small.

## Performance

### P1 — Catalog/collection score the full catalog per request, uncached — MEDIUM
- **Where:** `src/app/catalog/page.tsx` `loadMatches`, `src/lib/top-matches.ts`,
  `merge-worlds.ts` `mergedMatches` — loop over all 895 STRAINS × up to 3
  profiles; `evaluateFeedback` inside `scoreStrain` iterates every feedback
  signal per strain (O(strains × profiles × feedback) per page view). No
  `unstable_cache`/revalidate anywhere on this path.
- **What:** fine today; degrades linearly as feedback rows accumulate and the
  catalog grows. Server CPU cost on every catalog render for logged-in users.
- **Fix:** two cheap wins — (1) pre-resolve feedback strains once per request
  and pass resolved profiles into the loop instead of re-resolving per strain;
  (2) cache per-user match maps keyed on
  (profileUpdatedAt, feedbackCount, engineVersion) with a short TTL.
- **Effort:** medium.

## Tests / docs

### T1 — Test suite requires a generated Prisma client for 2 pure-ish suites — LOW
- **Where:** `tests/auth-core.test.ts`, `tests/taste-blender.test.ts` (imports
  `merge-worlds` → `prisma.ts` throws when the client isn't generated).
- **What:** 487/489 pass; the 2 failures in a fresh sandbox are environment

- **Fix:** a thin route-level test pass (node:test + fetch against `next dev`
  or route handlers invoked directly) for the top 5 routes: analyze, compare,
  profile CRUD, signup/login, feedback.
- **Effort:** medium.

### T3 — TESTING.md is stale — LOW

  assertions / 133 suites / ~11s.
- **Fix:** refresh the numbers; mention `npm run stress` snapshot-diff flow.
- **Effort:** trivial.
